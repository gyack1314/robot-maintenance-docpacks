# 演练来源接口与运行边界

来源服务仅提供虚构上游资料和收件端。通用表单供人工操作来源；基础校验不代替业务完整性判断。尚无面向值班员的采集、判断、续办或交付程序。

## 运行方式

Python 3.11，启动命令：python source_server.py --port 8765，页面 http://127.0.0.1:8765/ 。来源仅监听回环地址，重启恢复初态；验证客户端退出和续办时请保持来源进程运行。不依赖真实网站及账号。

## 资料和办理协议

/source-meta 给出分类、条数、整体版本、情景。/source-list?name=分类&offset=起点 每页两行，next 是下一页。整体版本不同不能当作同一依据。页面是虚拟滚动列表，详情需打开；浏览器专用分类在列表响应中只含标识和标题。/source-detail 是页面内部通道，要求网页采集的分类不得直接请求该接口或读取 sources 文件代替页面操作。其他分类可通过分页接口获取。

POST /exercise 的 id 对应页面情景，供人工改变上游事实，业务工具不能自动触发来获得有利结果。POST /source-action 载荷为 operation、object_id、request_key、expected_revision、payload。各操作字段由来源契约和 source.json.required_fields 定义。expected_revision 是核实的整体版本；过期返回409，字段不符接收端约定返回422，均无回执。

request_key 是本次办理身份，同键同内容重试只返回原回执，同键改内容拒绝。drop_response=true 或页面勾选连接中断会先受理再断开响应，/receipt?request=请求编号 与页面查询均可查真实结果。页面 receipts 分类可查看新回执。status、accepted、returned 由来源系统维护，不能从HTTP成功判断全部受理。办理本身增加来源版本，收件端不替代用户要求的业务判断。

/files/路径 提供真实原件、ETag、X-Content-SHA256和字节范围下载。传输摘要只说明实际收到的字节，不能替代供应商清单摘要。业务对象 identity 与整体 revision、各对象业务版本分别有不同作用。所有数据均为合成资料。

## 环境和测试

requirements.txt 精确固定浏览器依赖，正式离线使用前须预装依赖和Chromium。持久化浏览器资料放工作目录。python -m unittest discover -s tests -v 核验来源分页、收件、变化、原件传输及故障开关。python -m compileall -q source_server.py tests 核验语法。这些测试不证明尚待开发的业务功能完成；后续实现需补自己的使用说明及业务验证。
