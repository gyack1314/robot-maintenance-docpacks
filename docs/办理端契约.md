# 独立业务接收方

维修席位有generation及current_bundle，原件先经register_blob以实际hex和sha256登记，blob身份就是内容摘要。stage_bundle登记device、observed_at、documents、manifest、seat并创建不可覆盖bundle；manifest逐项含sha256、离线路径、文档身份。receive_bundle检查seat_generation后推进席位代际，旧包仍可追溯；一席位可接收多台设备，已接收历史不是自动删除。withdraw_bundle仅能撤待收包，announce_update只能给已收包追加更新通知。
维修资料中存在“主手册+必须绑定补充版”的成套关系，不允许选每个文档单独最新。一个blob可被多个设备包引用，也可能被不同文档身份引用，席位收到更新前仍须能取回旧包引用的字节。上传成功不表示资料适用或席位接收；席位只核实blob存在和接收代际，不替客户端解决设备部件适配及成套约束。
    
所有动作经来源页面表单或允许使用的来源接口传入operation、object_id、request_key、payload。每个payload带provider_version，当前版本与资源在provider_records分类取得。同键相同内容只受理一次，同键改变内容拒绝。业务拒绝不产生回执也不消耗版本；部分接受会产生回执并更新真实资源。动作不认可expected_revision为跨系统保证，接收端不能知道其他来源刚刚发生的变化。整体revision只用于辨认页面扫描是否混合了观察版本。操作字段完整清单见sources/source.json的required_fields；没有规定的业务归并、选择、恢复及展示均尚待开发。
